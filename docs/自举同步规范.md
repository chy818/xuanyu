# L1/L2 自举同步规范

> v0.4.0  
> 定义新语言特性在 L1 (Rust) 和 L2 (XY) 之间的同步流程、检查清单和验证标准。

---

## 1. 背景

玄语编译器有两套实现：

| 编译器 | 实现语言 | 定位 |
|--------|---------|------|
| **L1** (`src/`) | Rust | 生产编译器，全特性支持 |
| **L2** (`src/compiler_v2/`) | XY | 自举编译器，需与 L1 语义对齐 |

L2 的核心目标是验证语言的**自举能力**——即 XY 语言能够实现自身的编译器。因此，每当 L1 新增一个语言特性，L2 必须同步支持该特性的**语法解析和语义分析**，以保证 L2 能编译使用新特性的 XY 源码。

---

## 2. 编译器流水线

```
源码 (.xy)
  │
  ├─ 词法分析 (Lexer)   → Token 流
  ├─ 语法解析 (Parser)  → AST
  ├─ 语义分析 (Sema)    → 类型检查/作用域
  └─ 代码生成 (Codegen) → LLVM IR
```

同步要求按阶段递增：

| 阶段 | L2 同步要求 | 优先级 |
|------|------------|--------|
| 词法分析 | **必须** - 新关键字加入 `getKeywordId` 和 `是关键字` | P0 |
| 语法解析 | **必须** - 新语法结构加入递归下降解析器 | P0 |
| 语义分析 | **必须** - 新表达式/语句类型加入类型检查和符号解析 | P0 |
| 代码生成 | **尽量** - 新 AST 节点类型生成对应 IR | P1 |

## 3. 新特性同步检查清单

当 L1 新增一个语言特性时，按以下清单逐项确认 L2 同步：

### 3.1 词法分析 (lexer_s.xy)

- [ ] 新增关键字在 `是关键字()` 中识别（中文 + 英文别名）
- [ ] 新增关键字在 `getKeywordId()` 中映射到唯一 ID
- [ ] 若引入新 Token 类型，更新 `TokenType` 枚举（`types.xy`）

### 3.2 AST 节点 (types.xy)

- [ ] 新 AST 节点类型在 `AST节点类型` 枚举中定义（`types.xy`）
- [ ] 节点的 `kind` 编号不与现有节点冲突
- [ ] 如需要新标记位，优先复用 `intValue` 字段

### 3.3 语法解析 (parser_s.xy)

- [ ] 顶层声明分发（`parser分析Tokens` 主循环）添加新关键字处理
- [ ] 块语句分发（`parseBlock`）添加语句级处理
- [ ] 表达式解析添加前缀表达式处理（如 `await` / `spawn`）
- [ ] 新增解析函数，遵循 `parseXxx(p: Parser): AST节点` 签名
- [ ] `parser打印节点类型` 添加新 `kind` 的调试名称

### 3.4 语义分析 (sema_s.xy)

- [ ] `sema遍历表达式` 添加新表达式 `kind` 的类型推断
- [ ] `sema遍历语句` 添加新语句 `kind` 的分析流程
- [ ] 符号表操作正确（`添加符号`、`查找符号`）
- [ ] 类型兼容性检查覆盖新类型组合

### 3.5 代码生成 (codegen_s.xy)

- [ ] `codegen遍历语句` 添加新语句 `kind` 分发
- [ ] `codegen遍历表达式` 添加新表达式 `kind` 的 IR 生成
- [ ] 生成 IR 与 L1 格式对齐（以通过自举等价验证）

### 3.6 IR 等价验证

- [ ] 编写包含新特性的 XY 测试文件
- [ ] L1 编译测试文件 → IR1
- [ ] xyc 编译测试文件 → IR2（如 L2 codegen 不支持，可仅验证 parser/sema 通过）
- [ ] 对比 IR1 与 IR2（忽略临时变量名和标签编号差异）

## 4. 已知限制

### 4.1 Codegen 结构体字段上限

L2 的 `Codegen` 结构体字段数超过 19 个时，运行时会触发 segfault。因此：

- **禁止**向 `Codegen` 结构体新增字段
- 需要全局状态时，使用模块级 `定义 可变` 全局变量，在 `codegen遍历AST` 入口处初始化
- enum 判别值映射、async 函数信息等使用全局变量：`全局枚举值映射`、`全局异步函数信息`

### 4.2 L2 不支持 `引入` 多文件编译

L2 仅支持单文件编译。`引入` 语句在 L2 中仅作语法占位，不解析依赖。多文件项目由 L1 处理。

### 4.3 L2 codegen 覆盖面

以下 L1 特性在 L2 codegen 中**暂未实现** IR 生成（parser/sema 已支持）：

- `匹配` / `match` 语句
- `异步 函数` / `等待` / `启动` 表达式
- 枚举变体的判别值自动关联

这些特性在 L2 中可正确完成词法、语法、语义分析，但不会产出对应的 LLVM IR。

## 5. 验证流程

### 日常验证

```bash
# 单元测试
cargo test

# 自举脚本（快速）
bash tests/bootstrap_test.sh

# 自举脚本（完整）
bash tests/bootstrap_full.sh
```

### CI 门禁

CI 在 push/PR 时自动运行（`.github/workflows/ci.yml`）：

1. **Rust 测试** - `cargo test --all-targets` + clippy
2. **XY e2e** - 三平台端到端测试（hello, async, match, macro）
3. **自举门禁** - 逐模块 IR 验证 + 全流程自举脚本（Linux + Windows）

## 6. 同步案例：v0.3.0 async/match

以 v0.4.0 补齐 v0.3.0 的 async/match 特性为例：

| 阶段 | 改动 | 文件 |
|------|------|------|
| 词法 | 添加 `异步`/`等待`/`启动` 关键字 ID | `lexer_s.xy:153-155` |
| AST | 添加 `await表达式=31` / `spawn表达式=32` | `types.xy:68-69` |
| 解析 | `异步 函数` 声明 + `等待`/`启动` 表达式 | `parser_s.xy` |
| 语义 | await/spawn 类型推断，match 分支体遍历 | `sema_s.xy` |
| 回归 | `async_syntax_test.xy` / `match_syntax_test.xy` | `tests/bootstrap/` |
